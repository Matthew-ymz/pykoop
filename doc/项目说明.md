# 项目概览

当前仓库更接近一个围绕 Koopman 相关研究的实验仓库，而不是单一可发布包。结合根目录 `README.md`、`exp/`、`DeepKoopCE/`、`neural_science/`、`data_generators/` 与 `tools/` 的现状，可以确认其主要目标是围绕 Koopman coarse-graining、稀疏识别、动态系统建模以及部分神经科学数据处理开展实验、对比和结果沉淀。

从当前结构看，项目主要解决三类问题：

- 基于经典 Koopman / EDMD / ResDMD / SINDy 的动力系统分析与实验验证。
- 基于 `DeepKoopCE/` 的深度 Koopman 建模与 checkpoint 复现实验。
- 基于 `neural_science/` 的 EEG 数据读取、分阶段切分和后续实验准备。

其中“统一对外产品形态”目前待确认。现有仓库更明显地以 notebook、实验脚本、数据生成器和结果产物为主。

# 方法论与整体架构

当前可确认的整体组织方式如下：

- `data_generators/` 负责生成 Lorenz、弹簧振子等合成动力系统数据，为 `exp/synthetic_systems/pysindy/train_and_test.py` 提供输入来源。
- `tools/tools.py` 提供较大规模的通用分析函数，覆盖 Koopman 矩阵构造、伪谱分析、SINDy 拟合辅助、FFT、白化算子等能力，属于跨实验复用的工具层。
- `exp/` 是当前主实验目录，按课题拆分为 `air_quality/`、`kuramoto/`、`sir/`、`discrete_maps/`、`toy_nonlinear/`、`synthetic_systems/` 等子目录，主体形式为 notebook，另包含少量脚本入口。
- `DeepKoopCE/` 是相对独立的深度 Koopman 分支，包含核心模型实现 `deepkoop_func.py`、实验 notebook、LoRA/SVD 分析脚本与已保存模型。
- `neural_science/` 是另一条相对独立的数据处理与实验分支，先由 `experiments/read_data_improved.py` 读取 MAT 数据并切分阶段数据，再供后续 notebook 使用。

模块关系上，目前不是严格的包化架构，更像“共享工具 + 多实验分支”的研究目录。`exp/`、`DeepKoopCE/`、`neural_science/` 彼此相对独立，但都会依赖本地脚本、数据文件和第三方依赖。

# 目录结构说明

当前根目录下可确认的主要目录职责如下：

- `data_generators/`：动力系统数据生成器模块，包含 `base.py`、`lorenz.py`、`spring.py` 及站点 CSV 数据。
- `DeepKoopCE/`：深度 Koopman 实验分支，包含模型实现、实验 notebook、LoRA/SVD 补充脚本和 `model_save/` 模型文件。
- `doc/`：项目文档目录，当前可见 `研究框架.md`、本文件以及 `log/` 子目录。
- `exp/`：当前主要实验目录，承载经典 Koopman / SINDy / toy / air quality / Kuramoto / SIR 等实验。
- `neural_science/`：神经科学相关实验与预处理目录。
- `tools/`：通用工具函数目录，当前核心文件为 `tools.py`。
- `results/`：实验输出产物目录，当前已包含图片、模型文件和 `academic_experiment_visualizer_demo/`。
- `notebooks/`：当前仅看到缓存相关目录，是否仍作为正式实验入口待确认。
- `koopman for CE/`：当前仅看到 `.ipynb_checkpoints/`，该目录当前职责待确认。

当前可确认的结构变化/不一致点：

- 根目录现有主实验目录是 `exp/`，而 `README.md` 中仍多处写作 `experiments/`，说明文档与当前结构未完全同步。
- `pytest.ini` 仍引用 `tests`、`pykoop`、`examples` 作为测试路径，但这三个目录在当前仓库根目录下不存在，说明配置与现有目录结构存在脱节。
- 根目录存在 `DeepKoopCE/` 与 `neural_science/` 两条相对独立的研究分支，当前仓库已不是单一路径的实验组织。

# 主要文件说明

当前值得重点关注的文件如下：

- `README.md`：仓库总体说明文件，但从当前目录对照看，内容与现状存在一定滞后，尤其是 `experiments/` 命名仍未同步为 `exp/`。
- `requirements.txt`：运行实验所需基础依赖，含 `numpy`、`scipy`、`scikit-learn`、`pysindy`、`matplotlib`、`pykoop`、`sympy` 等。
- `requirements-dev.txt`：开发与文档/测试相关依赖，额外包含 `pytest`、`sphinx`、`snakeviz`、`mosek` 等。
- `pytest.ini`：测试发现配置文件；由于其引用的 `tests/`、`pykoop/`、`examples/` 当前缺失，因此需要重点核对是否已过期。
- `conftest.py`：pytest/doctest 辅助文件，明显面向 `pykoop` 包测试场景；与当前仓库主结构之间存在待确认的历史关系。
- `exp/koopman_ce_cases.py`：当前较关键的纯 Python 实验脚本，包含 case 配置、白化 Koopman 算子、分值比较和绘图等逻辑，可视为经典 Koopman CE 分析的脚本化入口。
- `exp/synthetic_systems/pysindy/train_and_test.py`：当前最清晰的脚本型运行入口之一；通过读取 JSON 配置、调用 `data_generators` 生成数据、训练并评估 PySINDy 模型，再输出结果到 `results/`。
- `tools/tools.py`：通用算法与分析工具集中地，体量较大、职责较重，对多个实验有潜在影响。
- `DeepKoopCE/deepkoop_func.py`：深度 Koopman 分支的核心实现文件，定义模型、损失函数、数据切片和训练辅助逻辑。
- `neural_science/experiments/read_data_improved.py`：神经科学分支的数据预处理入口，负责从 MAT 文件读取、过滤、标准化、切分并保存阶段数据。

文件关系上，当前较明确的链路有两条：

- `data_generators/*.py` -> `exp/synthetic_systems/pysindy/train_and_test.py` -> `results/`
- `neural_science/experiments/read_data_improved.py` -> `neural_science/visual_inducted_conscious/`（由脚本逻辑可知会向该目录写出阶段数据）

`DeepKoopCE/experiments/*` 与 `DeepKoopCE/deepkoop_func.py` 的关系可确认，但 notebook 级别的详细调用路径未逐一展开，具体依赖细节待确认。

# 运行方式与配置线索

当前可确认的运行/配置线索如下：

- 对于 PySINDy 实验，可直接运行 `exp/synthetic_systems/pysindy/train_and_test.py`，并通过 `configs/lorenz.json` 或 `configs/spring.json` 提供参数。
- 该脚本会把仓库根目录加入 `sys.path`，以便导入 `data_generators` 模块。
- 依赖清单主要位于根目录 `requirements.txt` 和 `requirements-dev.txt`。
- `DeepKoopCE/` 当前未看到独立的统一 CLI 入口，主要运行方式仍是 notebook 和分支内脚本，统一执行流程待确认。
- `neural_science/experiments/read_data_improved.py` 是数据准备入口，但它本身会写出数据文件，属于“预处理脚本”而非只读分析脚本。
- `results/` 目录中已存在 `sindy_model_spring.pkl`、`sindy_results.png` 等产物，可以反向印证 PySINDy 路径曾被实际运行。

从现有结构看，仓库更适合按“实验分支”理解，而不是按“单一应用入口”理解。

# 后续维护关注点

后续维护时，优先关注以下位置：

- `tools/tools.py`：该文件职责集中且内容庞大，若修改公共数学工具或拟合逻辑，可能影响多个 notebook/实验脚本。
- `data_generators/`：它直接影响 `exp/synthetic_systems/pysindy/` 的训练数据生成，改动会改变实验可复现性。
- `DeepKoopCE/deepkoop_func.py`：是深度 Koopman 分支的核心实现，改动影响模型定义、训练行为与历史 checkpoint 的兼容性。
- `neural_science/experiments/read_data_improved.py`：改动会直接影响 EEG 数据切分规则、输出目录内容和后续实验输入。
- `README.md`、`pytest.ini`、`conftest.py`：这几处与当前目录现状不完全一致，应优先核对其是否仍服务于当前仓库，还是保留了旧结构配置。

尤其需要重点关注的结构性问题：

- `README.md` 与实际目录命名不一致。
- 测试配置仍指向当前不存在的目录。
- 根目录项目名为 `pykoop`，但当前内容明显混合了 `KoopCE`、`DeepKoopCE`、神经科学分支和实验产物，仓库边界定义待确认。
